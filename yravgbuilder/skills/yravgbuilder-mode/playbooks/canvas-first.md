### Canvas first

**Big feature, redesign or parity port: coverage matrix and canvas before code.**

1. Collect every PRD row and every reference screen (help files, screenshots). Build the coverage matrix: row, screen, status.
2. Capture the real app chrome and the current screens (`spec-to-canvas` capture and slice scripts).
3. Draw every screen as a board in the real chrome, with Before / After, real states and one synthetic sample project.
4. Render the boards. Fix console errors, broken images and overflow. View the contact sheet yourself.
5. Publish and link the canvas. Send it to the owner. Stop for sign-off.
6. After sign-off, write the roadmap and handoff with one step per board, then run Feature delivery per board.

**Reply:** coverage matrix counts, canvas link, boards with open questions, what the owner must decide, what was not rendered.
