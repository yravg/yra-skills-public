# One improvement, then stop

**When:** a review or a failed run suggests a process or structure change.

Name the observed pain, the existing seam, the preserved behavior, and the rollback. Propose one change, or say none is justified. Do not start it unless the user asks for that change. Do not schedule a recurring refactor.

Rules:
- Prefer wiring a check the repo already has.
- Do not add a new instruction file when a test would do.
