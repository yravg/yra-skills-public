### Spec and tickets

**Turn an understood change into a local spec and vertical slices.**

1. If a decision still blocks the outcome, run `clarify.md` first.
2. Follow `../../to-spec/SKILL.md` for the spec shape. Write it in the reply, or in a path the user named. Do not publish it.
3. Follow `../../to-tickets/SKILL.md` for tracer-bullet slices, blockers, and a wide change's expand, migrate, contract sequence. Keep the tickets local until the user asks to publish.
4. For each slice, name the test approach and the stop condition.
5. Run the QA gate in `../../mattpo/SKILL.md`.

**Reply:** the spec, the slices, the blockers, and what you did not publish.
